# Domain docs

## Layout

This repository uses a single context:
- GLOSSARY.md: domain terminology.
- docs/adr/: architectural decision records.

## Consumer rules

Before exploring an area, read the root glossary and relevant ADRs.
Use glossary terms consistently in code, tests, issues, and proposals.
Explicitly identify conflicts with an existing ADR.

If a glossary term is missing, reconsider the terminology or record
the gap for domain modeling.

If domain documents are absent, proceed silently.
Create glossary entries and ADRs only when there is resolved
terminology or a consequential decision to record.
